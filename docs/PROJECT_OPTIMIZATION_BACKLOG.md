# SE-KB-Engine 超长优化任务清单

> 生成日期：2026-09-11  
> 目标：在不破坏现有爬取、抽取、精炼、检索、Web 与 MCP 能力的前提下，把项目逐步改造成可测试、可维护、可观测、可部署的工程。  
> 使用方式：按阶段顺序执行；每次只领取一个小批次；完成代码、测试、文档与验证后再勾选。`P0` 阻塞后续工作，`P1` 为高收益，`P2` 为增强项。

## 25. 当前盘点快照（执行前证据）

- 版本库当前约 138 个跟踪文件；存在用户未跟踪的软著文档、生成脚本与 `output/`，必须保留。
- Python 代码约 60 余个文件；正式 `tests/` 尚未建立，测试主要是 `scripts/test_*.py` 人工脚本。
- `server.py` 约 114KB、2700 余行，承载配置、Tor、搜索、抓取、图像、抽取、存储、检索和实时反馈。
- 当前 `compileall` 在 `server.py:1868` 失败；PowerShell 显示中文正常但 Python 按声明/默认编码解析为非法字符，需从字节层确认编码。
- Ruff 当前至少报告一个可自动修复的未使用 import；完整 mypy 结果尚需在修复语法后复测。
- `requirements.txt` 输出表现为 UTF-16/乱码；项目声明 Python >=3.13，而 Docker 使用 Python 3.10。
- `pyproject.toml`、开发 requirements 和生产 requirements 的依赖集合与版本范围明显不一致。
- `api/app.py` 的直接启动路径启用了 `debug=True`；Web 使用全开放 CORS。
- 管理/Web 端包含清空索引、重载等有副作用操作，需统一鉴权、CSRF 与审计。
- 抓取输入可触发任意 URL 请求，SSRF、防重定向绕过和响应上限是优先安全项。
- 代码存在大量宽泛异常捕获和静默 `pass`，会削弱故障诊断与正确降级。
- 跟踪文件包含约 68MB 的 `cloudflared.exe` 和 `web_cache.db`，需要确认版本化策略。

## 26. 优先级决策准则

按以下顺序选择下一项：安全/数据损坏风险 > 阻止安装启动测试的问题 > 建立回归安全网 > 正确性 > 可观测性 > 有测量的性能 > 架构整洁 > 体验增强。若两个任务收益相当，优先选择改动更小、可独立验证、回滚更容易的一项。
